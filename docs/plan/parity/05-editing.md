## 0. How the editor's keyboard model works today (needed to read the table)

1. **One global capture-phase key handler** (`app/src/lib/parancsok/kezelo.ts:7-23`, installed by `telepit` :25-29) maps the chord to a registry command *before* CodeMirror sees the event. Modifier-less keys (and Shift-only chords) are never intercepted inside editable elements, F-keys excepted (`kezelo.ts:12`, `billentyuk.ts:116-125`). A registry command wins over the same CodeMirror chord unless it is flagged `szerkesztoNyer` (`kezelo.ts:17`, `regiszter.ts:29-31`, used only by `panel.oszt-le`, `alapParancsok.ts:142`).
2. **The registry** (`app/src/lib/parancsok/regiszter.ts:55-74`) refuses duplicate ids and duplicate chords at registration; chords are canonicalised (`billentyuk.ts:60-67`). There is no persisted override table, so hotkeys are compile-time only.
3. **Hungarian layout rule** (`billentyuk.ts:1-5`, `docs/dev/DESIGN.md:135`): letters by `event.key`, digits by `event.code`, and chords that need AltGr on HU (`\ [ ] { }`) are avoided. This is why CodeMirror's `Mod-[`/`Mod-]` indent chords are effectively unreachable and `Tab`/`Shift-Tab` are the indent keys.
4. **CodeMirror keymaps** (`app/src/szerkeszto/beallitas.ts:120`): `closeBracketsKeymap`, `indentWithTab`, `searchKeymap`, `historyKeymap`, `defaultKeymap` (which includes `standardKeymap` and the macOS emacs-style `Ctrl-*` bindings). `markdown()` is created with the default `addKeymap: true` (`beallitas.ts:80`; `app/node_modules/@codemirror/lang-markdown/dist/index.js:398-407`), so `Enter` → `insertNewlineContinueMarkup` and `Backspace` → `deleteMarkupBackward` are active in both editing modes.
5. **Mode split**: the Notion layer (`/` menu, block handle, floating toolbar, table editor, `tablaVedo`) is loaded **only in Live Preview** via `elonezetMod()` (`beallitas.ts:83-85`, `notion/index.ts:14-16`); the formatting commands, `[[` completion, link click and the context menu are in the base extension list (`beallitas.ts:105-146`) and work in Source mode too.
6. **Precedence inside CodeMirror**: `Prec.highest` DOM handlers for the `/` menu (`notion/perjel.ts:193-220`), `[[` menu (`linkek/kiegeszites.ts:450-483`), AI link suggestion Tab/Esc (`asszisztens/javaslat.ts:312-332`) and AI continuation Tab/Esc (`asszisztens/folytatas.ts:157-169`); `Prec.high` for block Alt+↑/↓ (`notion/blokkfogo.ts:642-652`), table edge keys (`notion/tablazat/szerkeszto.ts:581-630`) and `[[]]` pair deletion (`kiegeszites.ts:502-516`). All of them check `isComposing`.
7. **Conflict guard**: `app/tests/billentyu-utkozes.test.ts:35-104` greps every `billentyu: '…'` in the sources and fails on an unlisted overlap with a CodeMirror keymap; the allowed exceptions are `Mod+F`, `Mod+Enter`, `Mod+Alt+ArrowDown`, `Mod+I` (`:74-83`). Any new chord proposed below has to go through this list.
8. **Availability gates**: `szerkeszt()` (`index.ts:49-52`) requires the editor to *have focus* (`p.fokuszban()` → `view.hasFocus`), so the formatting commands are hidden from the ⌘P palette while the palette owns focus; the Notion `notion()` helper (`index.ts:67-79`) does not require focus and refocuses the view before running — that is the better pattern.

Shipped editor chords today (`docs/dev/DESIGN.md:137-163` is the authoritative table): ⌘B/⌘I/⇧⌘H formatting (`index.ts:181-183`), ⌘K link (`:97`), ⌘↩ follow link when the cursor is on a link (`:119-133`), ⌘E / ⇧⌘E mode switches (`:148-165`), ⌘S (`:166-173`), ⌥⌘L formula OCR (`:186-197`), ⌘F search (`:198-209`), ⌘J / ⇧⌘J assistant (`:83-88`), ⌥↑/⌥↓ block move (Live Preview, `blokkfogo.ts:642-652`), F2 rename (`linkek/atnevezes.ts:190`), ⇧F10 / Menu key context menu (`helyiMenu.ts:90-101`).

## 2. Gaps and concrete proposals

All proposals stay inside the existing architecture: registry commands in `app/src/szerkeszto/index.ts`, CodeMirror extensions in `beallitas.ts` / `notion/*`, pure line-array operations in `notion/muveletek.ts` (pattern `szerkesztes(state, uj, kurzor)` :47-83 → one transaction), persisted preferences in `FeluletMentes` (`lib/elrendezes/felulet.svelte.ts:24-46`) through the existing `GET/PUT /api/felulet/allapot` (`docs/dev/ARCHITECTURE.md:194`; the core only checks "JSON object ≤ 256 KiB", `docs/plan/audit/03-felulet.md:222`). **No core endpoint change is needed for any gap below**; saving still goes through `PUT /api/vault/fajl` (`ARCHITECTURE.md:69`). Every new chord must be added to `app/tests/billentyu-utkozes.test.ts` (or be free of CM conflicts), and every new Notion-style operation should get a case in `app/tests/notion-obsidian.test.ts` (the C09 gate: Obsidian renders the result identically).

### 05-editing-01 — Toggle checkbox from the keyboard (`⌘↩`) · must · S · confidence high
*Obsidian*: `⌘↩` toggles `[ ]`↔`[x]` on every line of the selection; a plain or bullet line becomes `- [ ] …` (the last part: confidence medium). `⌥↩` follows the link under the cursor.
*Manifold*: toggle only by clicking the widget (`elo/widgetek.ts:293-299`, `Olvaso.svelte:94-111`); `⌘↩` opens the link or inserts a blank line (`index.ts:119-133`).
*Proposal*: new pure function `feladatValt(state): Szerkesztes | null` in `notion/muveletek.ts` (line-array walk over `state.selection.ranges`, `listaSorAdat` from `blokkmodell.ts:107-111` to parse the marker: task → flip `' '`/`'x'` (keep custom states as "done" → `' '`), list item → insert `[ ] `, plain line → prefix `- [ ] `; keep `userEvent: 'input.feladat'` as the widgets do). Register `szerkeszto.feladat-valt` in `index.ts` with `billentyu: 'Mod+Enter'`, available in `elo` and `forras` (use the `notion()` helper pattern but `elerheto: szerkeszt`-like without focus). Move `szerkeszto.link-megnyit` to `Alt+Enter` (Obsidian's default) — update `KIVETELEK` in `billentyu-utkozes.test.ts:74-83` (`Mod+Enter` is listed there with the link rationale) and `docs/dev/DESIGN.md:137-163`. Also expose it in the context menu (05-editing-15).

### 05-editing-02 — Line-level structure commands: Set as text / Heading 1–6, bullet, numbered, task, quote · should · M · confidence high
*Obsidian*: `editor:set-heading-0…6`, `toggle-bullet-list`, `toggle-numbered-list`, `cycle-list-checklist`, `toggle-blockquote` act on every selected line, in both modes, bindable; context menu *Paragraph* submenu.
*Manifold*: block-level *Átalakítás* only (`blokkfogo.ts:157-167`, `muveletek.ts:428-473`), H1–H3, cursor block only, LP only, refuses multi-line blocks for headings (`muveletek.ts:387-390`) and nested list items (`:382`).
*Proposal*: (a) add `Heading4-6` to `ATALAKITAS` (`blokkfogo.ts:157-167`, icons exist in lucide) and to `sablonElemek()` (`sablonok.ts:109-111`) — pure S; (b) new `notion/sorok.ts` with pure line-level toggles (`fejezetBeallit(state, szint)`, `listaValt(state, 'lista'|'szamozott'|'feladat')`, `idezetValt(state)`) over all selected lines using `listaSorAdat`/`fejezetSzoveg` (`blokkmodell.ts:107-111`, `:380-386`) and `szerkesztes()` for the single transaction; register `szerkeszto.fejezet-0…6`, `szerkeszto.lista-valt`, `szerkeszto.szamozott-valt`, `szerkeszto.idezet-valt` (no default chords; Obsidian has none either) in both modes; keep the block menu as the mouse path. Tests: extend `app/tests/notion-muveletek.test.ts` and `notion-obsidian.test.ts`.
