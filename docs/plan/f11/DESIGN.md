## First checkpoint

- Line transformations are shared between Source and Live Preview, keep multiple selections, protect non-prose syntax, and form one undo step. Cmd+Enter toggles tasks; Alt+Enter follows a link. H1–H6/text, list, task, quote and clear-format commands appear in the command palette. Source Cmd+K preserves the selection. Auto-pairs track only generated closing characters and leave code/YAML/links/comments alone; fence/display-math creation on blank lines takes priority over pairing.
- Local Markdown images use the existing embed renderer and core resolver. Markdown link targets are decoded once, after splitting the raw fragment. URI schemes never become vault API targets. Reading and both editor modes use the same core navigation and preview path; inactive LP links expose their labels. Arbitrary frontend path resolution is prohibited.
- Embedded task edits operate on the resolved target Dokumentum, validate the exact current core-provided slice and line, then use the existing atomic/CAS save path. The host note is never the implicit target. Read-only, stale and conflict states remain visible. Nested render cancellation follows the parent lifetime. CodeMirror widget resource ownership is attached to DOM lifetime, including equal-widget reuse.
- Content events refresh Reading/LP embeds independently of structural link-cache invalidation. Alias lookup follows both signals. Per-target refresh optimization and canvas-card refresh are still separate checklist work.
- Cmd+N and the new-tab create action open the existing safe name workflow. The quick switcher searches aliases and can create from Enter with no result or Shift+Enter. Explicit folder paths override the configured default; errors retain the name and allow retry. The core remains the exclusive authority for valid names and collisions.
- Pins survive workspace persistence. Group close operations preserve pinned tabs unless the user explicitly closes the whole group. Directional focus uses the actual split tree. Counts are keyed by tab and path, merge overlapping selections, and use Unicode word/grapheme segmentation; publication is deferred out of the keystroke transaction.
- Rich clipboard HTML is converted locally into Markdown through an inert, bounded parser. Files keep the attachment-import path; Shift+Cmd+V keeps plain paste. No scripts or remote resources execute. Conversion preserves code whitespace and falls back to plain text when bounds are exceeded.
- `%%` comments share one opaque parser between the views. Reading hides them; LP and Source show muted source as specified by audit 01. Existing PDF-highlight marker/block operations remain covered. Arbitrary inline-open comments spanning blank paragraphs are not yet complete.

## Second checkpoint: tags, unresolved links and explorer

The next batch implements body-tag parsing/style, shared fuzzy completion and click-to-search from Reading/Source/LP and property chips. Lexical vectors are compared against the real Python core regex, including Unicode decimal/non-decimal numbers, combining marks and whitespace differences. Tags keep the existing core grammar. Code, math, YAML, comments and link destinations remain protected; tags in link labels never produce nested interactive anchors. Tag search requires both the Tags and Search modules. The tag cache uses a shared, reference-counted lifetime and refreshes while an active editor needs it, even with a hidden tag sidebar.

Unresolved feedback is based only on confirmed core results. The editor processes visible ranges; Reader also observes asynchronously mounted nested embeds. Each resolution pass uses bounded batches and at most two requests in flight. Abort, document changes, structural/content generations and DOM identity prevent stale decoration. Unknown/failed/partial responses do not become missing-file state. The shared resolution service preserves cached and newly requested targets in mixed calls, preserves ambiguity, and invalidates on content events because an alias edit can resolve a former miss. This intentionally supersedes the first checkpoint's content-cache retention.

The explorer adds persistent name A–Z/Z–A and modified newest/oldest modes, with folders first and stable per-level ties. Date ordering asks for live metadata only while needed; default name ordering retains the existing per-save list-fetch avoidance. Expand/collapse covers empty and nested folders, preserves remembered opens and reports the 2000-open cap. Creation-time order remains open because the index/API has no real birthtime metadata; mtime is not used as a substitute.

After this batch the first remaining daily-use must work is property-type editing, completion of explorer creation-time order, and docked persistent search. Remote-image explicit downloads, partial multiline comment parsing and the other listed must/should gaps remain open. This remains an F11 checkpoint, not final phase closure.

Remote images remain a visible offline placeholder. D3 permits explicit downloads, not an automatic proxy fetch or a relaxed CSP; the implementation still needs a concrete user-triggered download path with bounds and error recovery. Existing AI features remain intact, with model/calibration changes reserved for their planned phases.

PLAN §10 names fourteen audits and a ranked critical top-25. Only eight audit documents are present. That source gap is recorded in the checklist; implementation proceeds on the available concrete requirements, without claiming the missing scope was audited or the final must100%/should80% gate was reached.

## Third checkpoint: property types, persistent search and Reading find

The property icon opens an explicit vault-wide type chooser. Save updates only `.obsidian/types.json`; it never rewrites a note or converts an existing value. Incompatible values remain visible. Tag/alias keys keep fixed types. The first-use automatic inferred-type registration is deliberately deferred so it cannot split the note-save transaction. Context-menu clipboard/remove actions remain open.

The metadata writer is a narrow exception to the hidden-path prohibition. Machine step tokens are denied; no automated caller is added. It validates bounded strict JSON, preserves unknown fields and exact numeric values, compares SHA-256 revisions, checks workspace identity independently of cached availability, and pins the root/config directory descriptors. All reads, temporary files and atomic replacements use the same descriptor. It requires a live snapshot store and a successful pre-snapshot containing the exact previous bytes; excluded/malformed/symlink files fail before replacement. A dedicated post-snapshot can be reverted using the existing snapshot endpoint. Post-replacement fsync or snapshot failure returns the new revision with an explicit uncertainty/warning, never a false untouched-file claim. Index timeouts also remain visible. External edits can still race the final CAS check and rename as in the existing optimistic note-save model; no cross-application lock is claimed.

The Search sidebar and Cmd+Shift+F overlay share one query/result/request owner and one extracted results component. Docking and result navigation retain the list and scroll. Sidebar view choice persists. Visible consumers share WS leases; the final release aborts pending work. Live refresh is debounced and retains the selected key. Overlay outro/focus restoration finishes before the dock or Reader search takes focus. Module gates remain active.

Reading Cmd+F searches native rendered Markdown text across inline formatting without changing modes, note bytes or editor history. Literal/case matching, Enter/ShiftEnter wrapping, Escape/focus return, collapsed callouts and asynchronous embed refresh are covered. Every result is navigable; at most 120 nearby logical results are marked at once. Interactive/opaque Svelte widgets, PDF content and math are excluded. Accent-insensitive matching and initial query transfer from the overlay remain open refinements.
